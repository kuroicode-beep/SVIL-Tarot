## 2. 신규 기능

### 2-1. 카드 크게 보기 (`src/components/CardViewer.tsx`)

`.card-img`가 `max-width: 220px`로 고정돼 있어 **저시력 사용자가 도판 자체를 판독할 방법이 없었다.**
타로 카드는 선이 가늘고 색이 많아 본질적으로 저대비다.

- 전체화면 확대 100~400% (step 25)
- 대비 강화 100~250% (`filter: contrast()`)
- 명암 반전 (`filter: invert(1)`), 뒤집기, 리셋
- Esc 닫기 + Tab 포커스 트랩, body 스크롤 잠금·원복
- 확대 시 넘친 영역에 닿도록 `justify-content: safe center` (일반 `center`는 왼쪽 넘침에 `scrollLeft`로 도달 불가)
- 카드명·정역 라벨을 상단바에 고정(확대해도 무엇을 보는지 잃지 않게)

조사한 경쟁 타로 앱(Labyrinthos·Golden Thread·Galaxy Tarot 등) 중 확대·대비 도구를 제공하는 곳은 **하나도 없었다.**

### 2-2. 문장별로 듣기 (`src/components/ReadingPlayer.tsx`)

`.ai-result`는 `white-space: pre-wrap` 장문이라 **읽던 위치(주시점)를 잃기 쉽다.**
W3C 저시력 요구사항 문서도 확대·서식 변경 중 주시점 유지를 핵심 요구로 든다.

- 문장 단위 분할 → 순차 낭독. 세대 카운터로 중지 시 다음 문장이 새지 않게 차단
- 현재 문장을 `▶` 글리프 + 왼쪽 굵은 막대 + `aria-current`로 표시(색 의존 없음)
- 문장 클릭 시 그 지점부터 재생, 이전/다음/처음부터 컨트롤
- 전각 문장부호(`。！？`) 분할 지원 — 공백을 쓰지 않는 ja/zh 리딩이 통째로 1문장이 되던 문제 해소
- Space 토글은 **플레이어 안에 포커스가 있을 때만** 가로챈다. 전역으로 걸면 8개 화면에서
  페이지 스크롤이 막혀 WCAG 2.1.4 소지가 있다
- 조합키 Space(Shift+Space 스크롤, Ctrl+Space 한/영 전환)와 키 연타(`e.repeat`)는 통과시킨다

AI 결과가 나오는 8개 화면(실전·AI타로·소울·오늘의한장·사주·궁합·성명학·작명) 전부에 적용.

### 2-3. 대비 프리셋 3종

다크모드는 만능이 아니다. 난시 사용자는 어두운 배경에서 밝은 글자가 번져 보이는 헤일레이션 때문에
**오히려 대비를 낮춘 쪽을 선호**한다는 조사 결과를 반영했다.

| 프리셋 | 본문 | 강조 글자 | 경계선(1.4.11) | 판정 |
|---|---|---|---|---|
| 표준 다크 | 17.80:1 | 11.35:1 | 3.47:1 | AAA |
| 초고대비 | **21.00:1** | 14.67:1 | 9.13:1 | AAA |
| 저글레어 소프트 | 13.66:1 | 8.81:1 | 4.12:1 | AAA |

전부 sRGB 상대휘도 공식으로 직접 계산했다. 셋 다 AAA(7:1)와 비텍스트 대비 3:1을 충족한다.

### 2-4. 그 외 접근성

- 글자 크기 5단계 (16/18/20/24/28px). `:root`의 `font-size`를 움직이므로 rem 요소가 함께 커진다
- 배경 장식 끄기 토글 — 그라디언트·상단바 블러·홈 카드 워터마크 제거
- `prefers-reduced-transparency` / `prefers-contrast: more` 시스템 설정 대응
- `@media (forced-colors: active)`에 `.reading-player__line--active` 추가

## 3. 잔여 검수 반영

### 3-1. 퀴즈 정답 쏠림 — 두 단계로 해결

**1단계(데이터)**: `minor-suits` 12문항이 **전부 `answerIndex: 0`**이라 첫 보기만 찍으면 100% 정답이었다.
채움 오답 2종(`"숫자만의 의미"`, `"스프레드 포지션 이름"`)도 12문항 공통이라 실질 선택지가 2개뿐이었다.
정답 문자열은 한 글자도 바꾸지 않고 위치만 재배치했고, 오답은 `cards.json`에 실존하는 의미로 교체해
**수트·정역·랭크 세 축을 모두 알아야 풀리게** 만들었다.

| 스테이지 | 이전 | 이후 |
|---|---|---|
| major-basics | 3/2/3/0 | 2/2/2/2 |
| major-middle | 1/3/5/3 | 3/3/3/3 |
| minor-suits | **12/0/0/0** | **3/3/3/3** |
| major-review | 6/1/8/7 | 6/6/5/5 |

**2단계(렌더)**: 검증 과정에서 균등 분포가 오히려 `01230123` 같은 **규칙적 수열**을 만든다는 게 드러났다.
`LearnQuizPage`가 JSON 순서를 그대로 그리므로 "1,2,3,4 반복"만 외우면 타로를 몰라도 만점이 나온다.
근본 해결로 **렌더 시점 셔플**을 넣었다 — 문항+세션 시드 기반 결정적 셔플이라 같은 문항을 다시 그려도
순서가 흔들리지 않고, 세션이 바뀌면 배치가 달라진다. 정답 판정은 이미 문자열 비교라 셔플과 양립한다.

최종 검사: 중복 0 · 범위이탈 0 · 카드의미불일치 0 · 정답 수열 주기성 없음.

### 3-2. 그 외

- **사주 원국 구조화 렌더** — `textBlock`은 Ollama 프롬프트 페이로드라 한국어를 유지해야 하는데
  화면에도 그대로 뿌리고 있었다. 년/월/일/시주를 `t()` 기반 정의 목록으로 분리.
  표 대신 세로 목록이라 저시력에서 행·열 추적이 필요 없다
- **음력 선택 즉시 경고** — 풀이를 돌린 뒤에야 경고가 뜨던 것을 select 옆에서 바로 알린다.
  `CompatPage`·`NamingPage`는 달력 입력이 없어 "항상 양력 기준" 명시
- **TTS 에러 i18n** — `tts.ts`가 던지던 한국어 문자열을 `TtsError` 코드로 전환
  (`tts_err_timeout`/`tts_err_play`/`tts_err_http`). 서버 응답 본문은 개인정보 우려로 콘솔에만
- **저장 문구 중복 제거** — 전역 배너를 실패 전용으로 좁히고 성공은 버튼 옆 로컬 메시지만.
  저시력 기준으로 화면 맨 위 배너보다 방금 누른 버튼 근처가 잘 보인다

### 4-1. 실제 브라우저 검증 (2026-08-09 추가)

사용자 지시로 내부 브라우저 금지를 해제하고 `npm run dev`(localhost:5173)에서 직접 확인했다.
스크린샷은 브라우저 페인이 화면에 표시돼야만 동작하므로, `javascript_tool`로 computed style과
레이아웃 수치를 직접 읽어 검증했다.

| 항목 | 실측 | 판정 |
|---|---|---|
| 홈 타일 바탕 | `rgb(28,36,49)` = `#1c2431` | 의도대로 |
| 홈 타일 글자·테두리 | `rgb(255,217,74)` = `#ffd94a`, 2px | 의도대로 |
| `:root` font-size (md) | **20px** (이전엔 16px 고정) | rem 수정 실증 |
| `.home-page` overflow | **visible** | 포커스 링 클리핑 해소 실증 |
| 대비 프리셋 강조 대비 | 표준 11.35 / 초고대비 14.67 / 소프트 8.81 | 계산값과 정확히 일치 |
| 초고대비 배경 그라디언트 | 자동 제거됨 | 의도대로 |
| 글자 크기 5단계 | 16 / 18 / 20 / 24 / 28px | 전부 반영 |
| 배경 장식 끄기 | 그라디언트·`backdrop-filter` 모두 none | 의도대로 |

**카드 확대 뷰어** — `role=dialog` · `aria-modal=true` · body 스크롤 잠금 · 열릴 때 '닫기'에 포커스.
Esc로 닫으면 body overflow가 `visible`로 복원되고 포커스가 '크게 보기' 버튼으로 반환된다.
핵심 검증인 **좌우 스크롤 도달**은 375px 뷰포트 / 400% 확대에서 확인했다 —
이미지 772px vs 스테이지 375px로 **가로 넘침 445px**인데 `scrollLeft=0`에서 왼쪽 여백 +24px,
`scrollLeft=max`에서 오른쪽 여백 +24px로 **양끝 전부 도달 가능**했다.
일반 `center`였다면 왼쪽 200px 이상이 영구 미도달이었을 것이다.

**문장별로 듣기** — 5문장 분할 정확(`.` `!` `.` `…` `
` 전부 경계로 인식),
현재 문장에 `▶` 글리프 + `aria-current="true"` + 노랑 6px 좌측 막대 + `#1c2431` 배경,
진행 표시 `1 / 5`, 터치타겟 50px. Space 가로채기는 **플레이어 안에서만** `defaultPrevented=true`이고
바깥에서는 `false` — 페이지 스크롤을 빼앗지 않는다(WCAG 2.1.4).

**퀴즈 셔플** — `minor-suits` 1번 문항에서 정답이 인덱스 2에 배치됐고(JSON 원본 순서와 다름),
문자열 판정이 정확히 `✓ 정답`을 붙였다. 답한 뒤에도 `aria-disabled="true"`라 포커스가 유지된다.

**사주 구조화 렌더** — 1990-03-15 13:20 입력 시 년주 경오 · 월주 기묘 · 일주 기묘 · 시주 신미.
수기 검산(일주: 1900-01-01 갑술 기준 32,945일 → 60간지 인덱스 15 → 기묘 / 시주: 기일 갑자시 시작 + 미시 → 신미)과 일치.
`<pre>` textBlock 노출은 사라졌다.

**전 화면 스모크** — 15개 라우트 전부 정상 렌더, JS 오류 0건, ErrorBoundary 발동 0건.
콘솔의 502는 Ollama·TTS 로컬 서버 미기동에 따른 프록시 오류로 예상된 것이다.

**여전히 미검증**: 로컬 TTS·Ollama를 실제로 켠 상태의 낭독 연속 재생과 AI 리딩 품질,
Windows 고대비 모드(`forced-colors`) 실제 렌더, 육안 스크린샷.
