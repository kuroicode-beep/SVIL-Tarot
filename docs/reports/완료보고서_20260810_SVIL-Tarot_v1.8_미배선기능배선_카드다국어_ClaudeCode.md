## 1. 이번 작업의 출발점

v1.7까지의 잔여 과제였던 **카드 다국어 배선**과 **`allSpreads()` 연동**을 처리하려고 소비처를
전수 조사하다가, 예상하지 못한 사실을 확인했다.

**완료로 보고된 기능 2종이 코드만 있고 화면에 연결돼 있지 않았다.**

| 모듈 | 규모 | 보고된 버전 | 실제 상태 |
|---|---|---|---|
| `src/lib/srs.ts` (SM-2 간격반복) | 245줄 | v1.6.0 | 호출하는 화면 **0건** |
| `src/services/exportReading.ts` (Markdown·인쇄 내보내기) | 376줄 | v1.6.0 | 호출하는 화면 **0건** |

두 모듈 모두 i18n 키까지 5개 언어로 준비돼 있었지만, 사용자가 누를 수 있는 진입점이 없었다.
`VERSION_HISTORY`의 1.6.0 항목도 사실과 다르게 적혀 있어 함께 바로잡았다.

> 확인 방법: `grep -rn "lib/srs\|exportReading" src/` → 자기 파일 외 참조 0건.
> 전 모듈 대상으로 같은 검사를 돌려 이 둘만 0건임을 확인했다.

## 2. 적용 내용

### 2.1 카드 다국어 배선 (78장 × 5개 언어)

`cards.i18n.json`은 v1.7에 만들어져 있었으나 `getLocalizedCard`를 호출하는 곳이 0건이었다.
en/ja/zh/vi 사용자도 카드 이름·의미가 전부 한국어로 나오고 있었다.

배선한 곳: `TarotCardView` · `CardViewer` · `DictionaryPage` · `StatsPage` · `DailyPage` ·
`LearnPage` · `ReviewPage` · `exportReading`

**지킨 경계** — 화면·낭독·문서는 로케일을 따르고, **LLM 프롬프트 페이로드는 한국어로 고정**한다.
프롬프트 언어가 사용자 로케일마다 흔들리면 리딩 품질·형식이 같이 흔들리기 때문이다.
`DailyPage`는 이 원칙에 따라 표시용(`getLocalizedCard`)과 프롬프트용(`getCard`)을 나눠 쓴다.

검색 보강: 화면 언어를 영어로 바꿔도 한국어 원본 이름으로 검색되게 건초더미에 원본 이름을 넣었다.
실측 — `"바보"` → 1건, `"컵"` → 14건, 검색어 없음 → 78건.

### 2.2 `allSpreads()` 연동

`PracticePage` · `AiTarotPage`가 `spreads.json`을 직접 import하고 있어 커스텀 스프레드가
목록에 나타나지 않았다. `PRESET_SPREADS`(동기 초기값) + `allSpreads()`(비동기 갱신)로 바꿨다.

- 첫 렌더를 빈 배열로 두지 않는다 — 선택값이 없는 상태에서 '뽑기'를 누르면 화면이 죽는 자리다.
- `SpreadsPage`에 '내 스프레드' 섹션과 `?spread=` 딥링크(`이 스프레드로 실전 보기`)를 추가.
- 프리셋과 내 스프레드를 색이 아니라 **글자**(`· 내 스프레드`)로 구분한다.

### 2.3 복습(간격반복) 화면 — 신규 `/review`

`srs.ts`에 `newCards(limit)`를 추가하고 `ReviewPage`를 만들었다.
`dueCards()`만으로는 첫 사용자가 영원히 0장이다(복습 대상은 이미 푼 카드뿐이라서).

- 진도 요약(전체·학습·오늘 복습·익힘) — 그래프가 아니라 '라벨 — 값' 정의 목록
- 카드 한 장씩 → 뜻 보기 → 4단계 채점. 뜻을 열기 전에는 낭독이 이름만 읽는다(정답 누설 방지)
- 취약 카드 Top 10 — 색이 아니라 `틀린 횟수 N회 · 난이도 계수 X.XX` 숫자로 표기

실측(브라우저): 8장 세션 완주 → `학습한 카드 0 → 8`, 취약 카드 `마법사 · 틀린 횟수 1회 · 난이도 계수 2.18`.
2.18은 SM-2 정의값(2.5 − 0.32)과 일치한다.

### 2.4 리딩 내보내기 배선

`HistoryPage` 상세에 '리딩 내보내기' 패널(Markdown 저장 / 인쇄·PDF)을 추가하고,
문서 라벨·카드 이름·의미가 화면 언어를 따르도록 `ExportOptions.locale`을 붙였다.

실측 출력:

```
ko : 1. [지금 상황] **완드 여왕** (Queen of Wands) — 정방향
en : 1. [지금 상황] **Queen of Wands** — Upright
ja : 1. **魔術師** (The Magician) — Upright
```

### 2.5 코드 분할 + 오프라인 유지

- 전 라우트 `React.lazy`, `AppShell`에 `Suspense`
- `deckUrl`을 `src/lib/deckUrl.ts`로 분리 — 홈이 장식 이미지 한 줄 때문에 카드 데이터
  152KB(`cards.json` 37KB + `cards.i18n.json` 115KB)를 진입 청크로 끌고 오고 있었다

| 항목 | 이전 | 이후 |
|---|---|---|
| 진입 청크 | 546.74 kB (gzip 149.90) | **419.34 kB (gzip 135.44)** |
| 청크 수 | 1 | 33 |
| 500 kB 경고 | 발생 | 없음 |

**오프라인 퇴보 방지**: 라우트를 쪼개면 '한 번도 안 들어간 화면'은 서비스워커 캐시에도 없어
비행기 모드에서 그 화면만 안 열린다. 첫 페인트 후 유휴 시간에 나머지 청크를 하나씩 받아 둔다.
실측 — 진입 청크 6ms, 프리페치 238ms 시작 → 375ms에 33개 완료.

### 2.6 i18n 정합성 게이트 신설

같은 검사를 세 번 손으로 돌린 뒤 스크립트로 고정했다.

```bash
npm run check:i18n
```

`t('key')`로 부르는데 사전에 없는 키, 언어별 키 집합 불일치를 잡는다.
`brand`·`settings_tts`는 고유명사·두문자어라 번역 대상이 아니므로 사유를 적어 예외 목록에 뒀다.
신설 직후 실제로 2건을 잡아냈다.

변경분을 5개 관점(로케일 / 스프레드 비동기 / SRS 상태기계 / 내보내기 / 번들)으로 나눠 탐색하고,

- 에이전트 34개 · 도구 호출 717회
- 주장 29건 → **확인 20건 / 반증 9건**

반증된 9건은 대부분 "사실이지만 이번 변경의 결함이 아님"(사전 존재)이거나 전제가 성립하지 않는 경우였다.

### 확인된 결함과 조치

**치명 2건 — 둘 다 이번 코드 분할이 원인**

| # | 내용 | 조치 |
|---|---|---|
| 1 | 서비스워커가 **SPA 폴백 HTML을 청크 `.js` URL에 캐시**해 그 라우트를 영구히 망가뜨림. 정적 호스트는 없는 파일에도 index.html을 200으로 주고, 캐시 우선 규칙 때문에 새로고침해도 복구 불가 | 문서 요청이 아닌데 HTML이 오면 캐시하지 않는다. 캐시 이름 `v1 → v2`로 올려 기존 오염분 폐기 |
| 2 | 청크 1개 로딩 실패가 **앱 전체를 오류 화면으로** 교체(ErrorBoundary가 라우터 바깥) | 본문 안쪽에 경계를 하나 더 두고, 경로가 바뀌면 자동 복구(`resetKey`). 청크 실패 전용 안내 + 1회 자동 재시도 |

치명 2건 실측:

```
청크 삭제 후 /review 진입
  이전 → 상단바 포함 화면 전체가 오류
  이후 → 상단바 7개 버튼 유지, 본문만 "화면을 불러오지 못했습니다" + 새로고침
캐시 검사 → 캐시된 JS 32개, HTML로 오염된 JS 0개, 없는 청크는 캐시되지 않음
청크 복구 후 새로고침 → 정상 진입
```

**주요 18건 중 조치한 것**

| 관점 | 내용 | 조치 |
|---|---|---|
| 로케일 | 영어에서 카드 이름이 두 번(`The Fool / The Fool`) — en 번역명이 `nameEn`과 78/78 동일 | `subtitleEn()` 헬퍼로 표시 이름과 같으면 부제·괄호·alt를 생략. 일본어는 `愚者 (The Fool)` 유지 확인 |
| 로케일 | 소울카드 기록을 영어로 내보내면 `**The Magician** (마법사)` | 부제를 저장본이 아니라 덱의 영어 이름에서 가져오도록 수정 |
| 로케일 | 배열 진단의 수트 이름이 한국어 고정 (`dict_suit_*` 키가 이미 있는데 미사용) | 사전 키로 넘기고 화면에서 번역. 프롬프트는 한국어 유지 |

| 스프레드 | 손상된 레코드 한 건이 내 스프레드 전체를 지움 | 건별로 거른다 |
| SRS | 채점 저장 실패가 성공과 구분되지 않음(무성 데이터 손실) | `recordAnswer`가 `saved` 플래그 반환, 화면이 알림 |
| SRS | 세션 끝에 포커스가 body로 떨어짐 | 완료 화면 제목이 포커스를 받음 |
| SRS | 빈 큐로 시작하면 화면이 그대로라 버튼이 죽어 보임 | 사유 안내 + 진도 재조회 |

| SRS | 처음 보는 카드는 무엇을 눌러도 내일인데 안내는 반대로 말함 | 새 카드 전용 안내 문구 |

| 내보내기 | 같은 버튼 재클릭 시 알림이 낭독되지 않음 | 비웠다 다시 넣어 내용 변화를 만듦 |

## 5. 남은 과제

| 내보낸 문서 제목 | 저장 시점에 한국어 리터럴로 굳는다(`실전 · …`, `AI · …`). 표시 제목을 저장하지 말고 kind+meta로 조립해야 하는 데이터 모델 변경이라 분리했다 |
